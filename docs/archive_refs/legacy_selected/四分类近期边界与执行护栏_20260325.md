# 四分类近期边界与执行护栏

> 更新日期：2026-03-25
> 用途：限制四分类主线近期只做必要验证，避免继续无边界扩散试模型。

## 一句话原则

四分类近期只允许做两类事情：

1. 完成少数已有主线实验的收尾和解释性整理
2. 围绕 `T2/T3` 做错误分析，而不是继续开新 backbone、新输入范式、新任务分叉

## 当前保留的参考实验

- `tstaging_4class_dual_v2_boundary_boost_frozen`

用途：

- 作为当前“边界增强是否有帮助”的主比较对象
- 继续观察 `T2/T3/T4+` 混淆是否下降

## 3. 三分类参考

## 近期允许继续执行的动作

## A. 补齐已有实验的 explainability 包

优先使用现有脚本：

```bash
python pipeline/scripts/postprocess_experiment_explainability.py \
  --exp-dir pipeline/experiments/<实验目录>
```

对重点 split 产出：

- `pipeline_review/`
- `ablation_pack/`
- 典型错误 atlas

## B. 做 `T2/T3` 错误分析

必须回答下面几个问题：

1. `T2` 被误分到 `T3` 时，模型到底在看哪里
2. 错误是否集中在某些来源、年份或 ROI 失败样本
3. 错误是否和分割失败、ROI fallback、低 Dice 有明显关联

优先使用：

- `pipeline/scripts/build_pipeline_error_review.py`
- `pipeline/scripts/postprocess_experiment_explainability.py`
- `pipeline/scripts/run_4class_gradcam.py`

## C. 只完成已经明确挂起的少量实验

如果 `docs/EUS_PLAN_NEXT_STEPS.md` 中仍有尚未完成且直接服务于主线判断的实验，可以继续完成。

但判断标准必须是：

- 能直接回答边界问题
- 能直接回答 `T2/T3` 问题
- 能直接形成对照结论

否则不继续补跑。

## 近期明确不再继续扩线的方向

以下方向默认暂停，除非先给出新的强证据：

- 新 backbone 大规模横向试验
- `predicted ROI` 路线的继续扩线
- `CORAL / ordinal` 类新分支
- 仅通过多训练轮数解决 `T2/T3`
- 只看验证集 AUC 的新模型筛选
- 和当前边界问题无关的输入花样组合

## 评估时必须固定看的东西

每次汇报四分类结果时，至少固定看下面 5 组信息：

1. 前瞻 / 外部 `AUC`
2. `BalAcc`
3. `T2 Recall`
4. `T3 Recall`
5. GradCAM 与错误 atlas 的人工解释

如果一个实验只能改善总 AUC，但 `T2/T3` 依然没有更清楚的解释，就不应定义为主线前进。

## 四分类近期的成功标准

未来两周内，四分类主线只追求下面 3 个结果：

1. 把当前最值得保留的 1 到 2 条路线说清楚
2. 把 `T2/T3` 错误模式说清楚
3. 把“是不是需要重构任务定义”说清楚

## 什么时候考虑任务重构

若出现以下情况，应讨论是否把主线临时重构为分层任务：

- 四分类继续无法稳定提升 `T2/T3`
- 边界相关证据在良恶性上先被证明更有效
- 方向性标注试点显示比现有标签更接近医生决策逻辑

重构顺序建议为：

1. 先良恶性
2. 再局部突破识别
3. 最后再回四分类

## 对内汇报的固定话术

建议统一说：

- “四分类近期不是继续开新模型，而是收口到边界相关验证和 `T2/T3` 错误分析。”
- “任何新实验都必须说明它是帮助判断主线，还是只是在增加实验数量。”
- “如果一个方向不能帮助解释 `T2/T3`，就不应进入近期优先级。”
