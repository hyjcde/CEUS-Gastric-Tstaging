# 方向性标注试点方案

> 更新日期：2026-03-25
> 用途：在不要求医生大规模重画 mask 的前提下，先验证“突破方向”这类轻量监督是否有价值。

## 试点目标

这次试点不是为了直接造一个完整新数据集，而是先回答下面 3 个问题：

1. 医生能否稳定地给出“最可能突破方向”
2. 哪种标注形式最省时、最不容易歧义
3. 这种轻量信号是否值得后续接入模型

## 默认选择的试点顺序

建议默认顺序不是三种一起上，而是：

1. **主方案：`8sector` 扇区点选**
2. **对照方案：`3x3` 九宫格点选**
3. **备选方案：`4x4` 细网格**

原因：

- `8sector` 最贴近“方向”这个临床概念，医生更容易表达
- `3x3` 更直观，适合快速确认是否需要更粗粒度表达
- `4x4` 信息更细，但认知负担更高，不应一开始就默认主推

## 试点病例怎么选

第一批只建议放几十例，优先挑下面几类：

1. `T2/T3` 混淆最典型的病例
2. GradCAM 看起来接近边界、但模型仍分错的病例
3. 同一病人不同切面里判断不一致的病例
4. 医生认为“有明确突破方向”的典型病例

不建议把明显看不清或标签本身就高度不确定的病例放进首批试点。

## 医生真正需要做什么

医生不需要画新的精细 mask，只需要做下面一件事：

- 在病灶附近选出“最可能发生突破的方向或区域”

默认规则：

- 优先只选 1 个主区域
- 若确实存在 2 个相邻候选方向，可以允许最多选 2 个
- 不要覆盖整个病灶内部
- 不要把标注当成重新画病灶边界

## 推荐记录字段

首批试点最少记录这些字段：

- `case_id`
- `patient_id`
- `image_path`
- `roi_path`
- `label`
- `predicted_stage`
- `priority`
- `source`
- `annotation_modes`
- `selection_reason`
- `doctor_notes`

模板文件：

- `docs/方向性标注试点模板.csv`

## 现在新增的转换脚本

为了后面接浏览器标注工具，新增了一个 manifest 生成脚本：

```bash
python pipeline/scripts/build_directional_annotation_manifest.py
```

默认读取：

- `docs/方向性标注试点模板.csv`

默认输出：

- `pipeline/experiments/annotation_pilot/directional_annotation_manifest.json`

这个 JSON 可以作为后续轻量标注小工具的输入。

## 推荐的试点节奏

### 第 1 步：先建病例池

- 先从错误分析和典型病例里挑 20 到 50 例
- 每例都给出“为什么值得标”的原因

### 第 2 步：先试 `8sector`

- 先让医生用 `8sector` 点选
- 同时保留少量病例做 `3x3` 对照

### 第 3 步：只看稳定性，不急着进模型

第一轮先回答：

- 医生是否愿意标
- 平均每例花多久
- 有没有大量“选不出来”的情况
- 两位医生是否大致一致

### 第 4 步：再决定是否扩大

只有当下面几件事同时成立，才考虑扩大标注：

- 医生认为形式可接受
- 标注时间可控
- 结果没有大量歧义
- 与当前 GradCAM / 错误分析存在可解释对应关系

## 试点成功标准

首批试点只要达到以下 4 条中的 3 条，就算成功：

- 大多数病例可以在 30 到 60 秒内完成标注
- `8sector` 的理解歧义明显少于 `4x4`
- 医生能在典型 `T2/T3` 病例上给出比较明确的主方向
- 标注结果和现有错误分析、GradCAM 有可对照关系

## 暂时不要做的事

当前先不要做：

- 大规模精细突破区域 mask
- 一开始就做多医生大规模一致性统计
- 还没完成首批试点就直接改模型训练代码
- 同时推出太多标注形式给医生比较

## 对模型侧的意义

这条线如果成立，后续可支持至少三种方向：

1. 作为 explainability 对照标签
2. 作为边界附近的辅助监督
3. 作为“先方向、后分期”的中间任务

但在试点完成前，不默认承诺直接进入模型训练。
