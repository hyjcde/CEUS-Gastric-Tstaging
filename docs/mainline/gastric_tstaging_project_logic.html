§2 临床终局

场景

模态经腹胃充盈超声（水充盈），非 EUS
主任务术前 T 分期四分类
形态Agent → 结构化 JSON → 医生工作台
定位分流与辅助决策；不替代 EUS 的 N/M

为何 T 分期是核心

  • 患者级 pT 标签 + 多帧噪声
  • 关键切面不总在每一帧
  • T2/T3、T3/T4+ 是真实瓶颈
  • 分割 Dice 高 ≠ 分期正确

Agent 输出：综合结构化 JSON（非单句结论）

一次「运行 Agent」会依次调用分割、T 分期分类、形态学、临床风险、报告文本、相似病例、知识库等工具， 并可能调用 DINO 特征可视化、胃壁穿透图、可选 LLM 报告润色。 因此返回给前端的是一整包可追溯证据，而不只是 recommended_T_stage 一个字段。

实现入口：pipeline/agent/product/analyze_case.py → POST /api/agent/analyze（Next.js 转发）。

医生可读层（Workbench 主展示）

  • report — 推荐 T、置信度、支持/不确定理由
  • report.dynamic_report_draft — 可复制中文报告草稿
  • similar_cases — 相似病例与预览图
  • prediction_artifacts.*_url — 分割叠加、T 概率条、DINO、胃壁图

审计 / 科研层（完整 payload）

  • tool_evidence — 各工具原始输出
  • agent_steps — 逐步推理轨迹（intent / decision / reasoning）
  • traces — 工具调用简表
  • runtime_verification — 是否真实调用了各模型 API
  • trajectory_ref — 落盘 JSON 路径

  • 数据层：同一 patient_id 常有多帧（建模 CSV 有 1,093 行重复图像视图），病理 pT 为患者级
  • analyze_case.py：前端 payload 虽有 frame_count，主路径对单张 image_path 跑分割+分类+相似病例
  • EvidenceHub（evidence_hub.py）：支持多帧质量加权、帧间一致性 — 主要用于 run_agent_eval.py / ReAct 评估，未作为 analyze_case 主入口
  • 实验：patient_mil_image_dino_fusion 报告前瞻泛化差；dinov3_framelevel_scalar_* 有帧级训练+患者聚合 — 未固化进 Agent

目标：关键帧选择（最深侵犯）+ 患者级 T 概率；与 T 分期训练时的 MIL 策略与 Agent 推理一致。

⑥ 证据 Schema 与融合逻辑 P1 · 阶段 B

现状：

  • 产品入口：_build_rule_based_report（analyze_case.py）— 非独立 EvidenceSynthesizer 类；schema_version: 0.2.0
  • 融合方式：分类概率 + 形态/临床/报告启发式加分 + 相似病例固定权重 0.35×占比 — 无可学习的 rag_weight
  • 输出字段：supporting_evidence、uncertainty_flags；无结构化 conflicting_evidence（ReAct/EvidenceHub 路径有）
  • 评估契约：docs copy/technical/AGENT_FRONTEND_REPORT_SCHEMA.json 与 analyze 返回 JSON 字段未完全对齐
  • 前端 patient.agent_report 仍可能显示「Dual-branch classifier not connected」— 与真实 Agent 结果易混淆

目标：统一 ToolOutput → EvidenceBundle → PatientTReport；实现科研计划中的 final_T = base×(1-w) + rag×w；冲突/抑制子组可评估。

⑦ Stage-1 工具链未闭环 P2 · 阶段 B+

现状：

  • SegmentationTool：ConvNeXt-UNet fulldata / strict fallback — 可用，Dice 与中心相关
  • 无独立 LumenDetectionTool（YOLO 在 experiments/baselines/detection_baseline_v1/，未进 Agent registry）
  • Wall 证据：优先复用离线脚本 PNG（wall_penetration_analysis/per_sample），否则 live proxy 热图 — 不是在线 wall-band 特征张量
  • region contrastive / breakthrough 特征已在训练 CSV（region_contrastive_full），Agent 未读 region patch 或 boundary head

⑧ 闭环关系（为何先 A 后 B）

flowchart LR
  A[① 资产审计\n定 T/seg checkpoint] --> B[④ Split 重建]
  B --> C[② 接 ClassificationTool]
  C --> D[⑥ 证据 schema + ⑤ MIL]
  D --> E[③ DINO RAG + RAGGate]
  E --> F[⑧ 前端对齐\n冻结验证]

不做 ① 直接改 ②，容易再次接错 checkpoint；不做 ④ 就训 RAG/报外部 AUC，审稿风险高。

工具链顺序（T 权重最高）

1. YOLO 胃腔→ 2. 分割 mask/ROI→ 3. Wall-band→ 4. DINO 区域（可选）→ 5. 多帧 MIL→ 6. T 分期分类 ★→ 7. 临床 / 报告→ 8. Case-RAG + Gate ★→ 9. 证据合成→ 10. Memory / 轨迹

融合公式（T 为中心）

final_T_probs = base_T_probs × (1 − rag_weight) + case_vote_T_probs × rag_weight

base 来自 ConvNeXt T 主线 · rag_weight 由 mask 质量、检索 entropy、T2/T3 边界、base-RAG 冲突决定 · 良恶性不覆盖 T 主结论
