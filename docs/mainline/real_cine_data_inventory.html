1. loop 到底是什么？

loop_still = 静图循环伪视频：没有真实超声 cine 录像时，预处理把 一张 JPG/BMP/静帧用 ffmpeg 的 -loop 1 重复编码成短 MP4，好让前端/管线统一读“视频文件”。

源
单张静图
例：1000012-1.jpg
→
ffmpeg
-loop 1 · 约 5s · 10 fps
50 帧内容完全相同
→
产物
crop_ui/videos/*.mp4
mode=loop_still · ~70 KB
源
真实 cine / AVI / MP4
有时间维、探头运动
→
ffmpeg crop
按 ROI 裁切转码
帧间有变化
→
产物
crop_ui/videos/*.mp4
mode=cached · 常配 raw

生成代码（仓库内）

scripts/crop_prospective_reader_videos.py → write_loop_mp4_from_still()： 

ffmpeg -loop 1 -framerate 10 -i frame.png -t 5 \
  -vf format=yuv420p -c:v libx264 -an out.mp4

实测对比（抽检）

类型 典型时长 帧数 体积 帧间平均差分 含义
loop_still 5.00 s 50 ~0.07 MB ≈ 0（25/25 样本） 静图重复，无时间信息
cached + raw+crop ~3–6 s 可变 常 >0.3 MB 中位 ~3.3（多数有运动） 更像真 cine
cached + crop_only 常 5.00 s 常 50 常 ~0.07 MB 抽检也常 ≈ 0 标签写 cached，但部分仍可能是静帧产物
注意：registry 里 video_mode=cached 来自 dataset/video_crop_report_*.csv 的预处理 mode 字段，表示「当时按视频缓存路径写出」， 不等于已经过运动检测。 更强信号是 video_match_status=raw+crop（能对上原始录像）。 监督集 2731 里：raw+crop 1297，crop_only 1434。

为什么训练不用 loop？ 模型若当视频吃，学到的是「同一帧重复」，不是胃壁随时间的动态；会污染时序特征。图像模型仍可直接用对应 JPG。
