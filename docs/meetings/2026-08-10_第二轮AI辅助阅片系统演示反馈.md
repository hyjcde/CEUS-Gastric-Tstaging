## 三、临床侧产品优先级（明确，勿偏离）

1. **医生会找病灶**：不必把大量时间花在「AI 必须自动找准病灶/胃腔」。医生自己会做，AI 只要协助即可。  
2. **AI 价值在分析**：尤其是 **T2 vs T3 不确定时**，要展示分析过程、分类/分期证据，帮助复核。  
3. **关键帧可由医生自选**：算法关键帧不准可接受；界面挤、关键帧不准都不阻塞；重点是分析页与证据。  
4. **勾画够用即可**：大概勾出病灶与胃腔后，再生成结构化/边界/T 证据即可；不必追求完美勾画。  
5. **病灶与胃腔相对准 → 分析才准**：突破附近特征依赖两者相对位置；画太偏会找不到突破区。  
6. **结果不能「一眼乱」**：格式与思路对了，仍需个案看准不准；要能提供可复核依据，而非空结论。  
7. **愿景（非当场验收数字）**：口语期望在 AI 帮助下准确率有实质提升（约 40% → 70–80%）。  
8. **最终判断在医生**：看完 AI 分析后做最终复核；不以「点了采纳」代替临床判断。

## 四、约定工作流（双方口头确认「整个逻辑可以」）

```text
播放视频
  → 医生选关键帧（可自选，不强制依赖算法关键帧）
  → 勾画/精修病灶 + 胃腔
       · 胃腔必须包含胃壁与肿块区域（不能画得太局限）
       · 病灶应在胃腔语义内（避免「病灶在胃腔外」违和）
       · 可先自动检测胃腔，再人工调整；病灶可用框选/正负点/涂鸦/手动精修
  → 生成：边界分析 + T 分期结构性证据 / 模板报告
  → 医生查看 AI 分析过程、思考步骤与依据（重点）
  → 医生最终复核与判断
  → 模板报告（层次结构为主；边界/形态写入模板；可切换总览等导航）
```

## 五、演示中暴露的问题（按主题，尽量不漏转写）

### 5.1 分割与解剖定义

- 胃腔轮廓画得太局限；**胃腔肯定要包括胃壁，以及肿块**。  
- 病灶应在胃腔语义内；演示中出现「病灶相对胃腔外」的违和感（双方都觉得「怪怪的」）。  
- 胃腔自动检测尚不够准（训练数据不足；集成的是既有模型）；可先检测再人工调整。  
- 病灶勾画相对准 + 胃腔相对准，突破附近特征才找得到；否则分析容易偏。

### 5.2 轮廓编辑交互（高优先级；含老板此前意见）

- 编辑框/控制点过大，小病灶会被覆盖，边界修不好（老板说过同类问题）。  
- 可编辑点需更密；控件做成透明/半透明，不挡病灶。  
- 线过粗、点过大、颜色过深，干扰判断 → 需变浅变细。  
- 框选完成后误切到默认点选 → 框选逻辑需修。  
- Tooltip 悬停文案挡画面；工具栏文字可常显，少靠悬停。  
- 浏览器翻译插件（红色圆圈）会挡住最右侧打开侧栏的箭头 → 需兜底（默认开侧栏等）。

### 5.3 工具栏、入口与布局

- 左栏：病灶相关（正负点、涂鸦、框选、精修等）。  
- 右栏：胃腔相关（检测胃腔、调整胃腔轮廓等）。  
- 字标曾因占位过大被去掉 → 需再平衡「可读 vs 占位」；会议倾向把字再标出来，同时删低频工具。  
- 低频/不好用工具可删，把最重要操作放到最显眼位置；整体布局还要再改一轮。  
- 左右分栏也可评估「弄到一起」，以测试迭代为准。  
- 「辅助意见」入口不够醒目 → 放到类似「视频跟踪」的大按钮位置（图像顶上正中）。  
- 辅助意见侧栏可考虑默认打开（避免被翻译插件挡住还找不到）。  
- 按钮逻辑与操作顺序需再梳理（先勾画再分析等）。  
- 放大查看需更接近「放大镜」：鼠标滑动查看局部高倍细节（突破区附近），而非当前不够用的放大。  
- 布局按常见显示器 **1920×1080** 再压信息层级；演示时建议全屏（F11）观感更好。  
- 模板报告页：可切换总览等导航；关闭工作台后右上角关闭、左下角壁层/边界入口等仍需排版优化。

### 5.4 分析、进度与性能

- 全视频跟踪与分析约 **30–40s**；不能干等 → **全局进度条 + 当前步骤提示**（不止按钮状态；口述可放页面左下角一类固定区域）。  
- 网络卡顿导致操作「没反应」；涂鸦/计算也会慢；需有保存与明确反馈。  
- 公网服务器资源有限，视频不宜堆太多。  
- 临床侧主要看分析页面：要看到「怎么思考/分析到哪一步」，避免前台长时间无步骤信息。  
- 演示当日分析质量仍不够好（「分析的不是很好」）→ 下午集中改，晚上再发链接复测。

### 5.5 报告、关键帧与证据渲染（bug / 未上线）

- 报告渲染有问题（当天下午继续改；报告系统已升级一轮）。  
- 视频证据帧渲染有问题；当前帧结果展示链路不稳。  
- 边界分析算法复用已有实现，但**当时尚未部署到公网服务器**，演示打不开。  
- 关键帧算法不准 + 界面位置挤（曾放顶上）；临床接受医生自选关键帧。  
- 边界分析报告、整段视频生成、每帧可编辑等能力需在公网链路打通后才能给临床侧稳定试用。

### 5.6 域名与入口

- 公网入口已收敛为单一干净 HTTP 地址。  
- 内测后可用 `gastric ultrasound` / 胃超声类 `.com` 域名；输入域名 + 密码进入系统。  
- 黄逸君会发**候选表**供临床侧选择偏好（主要看前缀；后缀一般 `.com`）。  
- 临床侧对具体名字无强偏好，「随便选一个都行」；**固定下来方便测试即可**。  
- 注册后配置部署，使域名专属本系统入口。

## 七、验收时「什么算好」（从会议语言提炼）

| 维度 | 好的标准 | 明确不要求 / 勿本末倒置 |
|------|----------|-------------------------|
| 找病灶/胃腔 | 医生能快速粗勾；自动检测不准可接受 | 不要求 AI 病灶/胃腔检测「多么强大」 |
| 关键帧 | 医生自选可用 | 不要求算法关键帧先准 |
| 分析页 | 有思考过程与 T2/T3 等依据；不像乱分析 | 不能只有结论没有依据 |
| 报告 | 层次为主，边界/形态在模板内；能渲染 | 不因排版/bug 读不了 |
| 交互 | 小病灶可修；不挡视野；长任务有进度 | 不因控件/tooltip/翻译插件无法操作 |
| 组织 | 先内测再扩专家 | 不在系统粗糙时直接开全量第二轮 |
| 研究目标 | 希望准确率质的飞跃（口语 40→70–80） | 该数字是愿景，不是当晚验收阈值 |

## 八、即时时间线（会议约定，摘要）

1. **当天下午**：集中改交互、分析展示、报告/证据渲染、控件与入口。  
2. **当天晚上**：同一链接再发临床侧复测。  
3. **随后**：临床侧与老板先内测；够稳再扩其他专家做第二轮。  
4. **并行**：域名候选确认 → 注册 → 部署入口固定。  
5. **更后**：第二轮结果 OK → 改论文投稿。
